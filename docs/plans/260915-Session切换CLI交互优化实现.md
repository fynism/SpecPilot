# Session 切换 CLI 交互优化实现计划

## 背景与结论

当前 `/switch <session-id>` 要求用户记住完整 Session ID。`SP-467d4771ec08` 已明确将本次
优化限制在 CLI 与终端适配层：无参数 `/switch` 提供可选择的 Session 列表，确认后继续调用
现有 Session 切换流程，不改变 Agent Loop、Session 生命周期、Spec 隔离或持久化格式。

该边界总体合理，既改善常用交互，也保留脚本通过完整 ID 直接切换的稳定路径。实现依据
`R-001`—`R-009`、`D-001`—`D-008` 与 `AC-001`—`AC-010`。

实施前建议对 Spec 做一次非语义性整理：`OQ-001`—`OQ-004` 已分别被 `D-002`、`D-003`、
`D-004`、`D-006` 回答，不应继续表现为未决问题；范围中的 `S-005`、`S-006`、`S-007`、
`S-008`、`S-010` 实际是排除项，宜与纳入项分开表述。这些文档问题不改变本计划采用的行为
边界，也不应由实现代码擅自改变 Spec。

## 实现边界

本次只完成以下内容：

- 无参数 `/switch` 打开 Session 选择器；带完整 ID 的原路径保持不变；
- TTY 环境提供方向键选择、分页、确认和取消；
- 非 TTY 环境提供一次性编号列表及序号输入回退；
- 列表统一按 `updated_at` 倒序展示短 ID、标题、状态、最近活动时间和消息数；
- 确认后沿用已有 `session_changed` 返回值、运行时重建及 interrupted 提示。

本次不做搜索、标题自动概括、澄清组件重构、持久化迁移、多进程并发、跨 worktree 共享，
也不改变其他 Session 命令的输出。（`R-002`、`R-006`—`R-009`）

## 技术思路

### 1. 独立终端适配器

在 `specpilot/integrations/terminal/session_picker.py` 实现独立 Session Picker，不复用或修改
澄清 presenter。选择器只接收 Session 列表和当前 Session ID，返回被确认的 Session ID 或
取消结果；它不直接读写 Session Store，也不负责切换。（`D-002`、`D-008`，`AC-006`、
`AC-010`）

将列表排序、字段格式化、页码计算和高亮位置计算保持为无副作用逻辑。TTY 的输入、输出对象
可注入，非 TTY 的读取与输出函数也可替换，使测试不依赖真实终端。

### 2. TTY 选择流程

使用现有 `prompt_toolkit` 依赖构建单选界面，每页固定 10 条。进入界面时先定位当前 Session
所在页并高亮当前项；`↑/↓` 只在当前页移动，`PgUp/PgDn` 与 `n/p` 翻页，页面变化后高亮落在
该页有效项上。只有 Enter 确认才返回目标 ID，Esc 或 Ctrl+C 返回取消。（`R-004`、`R-005`、
`R-009`，`AC-002`、`AC-003`、`AC-008`）

### 3. 非 TTY 回退

当标准输入或输出任一不是 TTY 时，一次性打印排序后的全部 Session，并使用从 1 开始的编号
读取选择。空输入、越界值和非数字输入只显示明确提示并继续等待；EOF 或 Ctrl+C 视为取消。
该路径不输出控制序列、页码，也不要求翻页。（`R-003`、`D-003`、`D-007`，`AC-004`、
`AC-009`）

### 4. CLI 接入

扩展 `handle_session_command` 的无参数 `/switch` 分支，通过可注入的 picker 获取目标 ID。
取消时直接返回 `handled`，不得调用 `SessionManager.switch()`；确认时调用现有 `switch()`，并
复用带参数路径的成功提示、错误处理和 `session_changed` 结果。CLI 主循环继续只在等待用户
输入时处理命令，并在 `session_changed` 后重建当前 Session 的 Agent Runtime。（`R-001`、
`R-004`、`R-006`、`R-007`，`AC-001`、`AC-003`、`AC-005`）

为避免两条切换路径日后产生提示差异，可以在 CLI 内部收敛“按 ID 执行切换”的小函数；这只是
表现层去重，不改变 SessionManager 接口或行为。

## 测试与验收

1. 为纯列表逻辑测试字段、倒序排序、短 ID、消息计数、页数和当前项初始页。
2. 使用 `prompt_toolkit` 的虚拟输入输出驱动上下移动、跨页、确认、Esc 和 Ctrl+C；覆盖恰好
   10 条、11 条及当前 Session 位于后续页面的情况。（`AC-002`、`AC-003`、`AC-008`、
   `AC-010`）
3. 为非 TTY 回退覆盖全部列表输出、空值、非数字、越界、重试后成功、EOF 与 Ctrl+C 取消。
   （`AC-004`、`AC-009`）
4. 扩展 CLI 命令测试，验证无参数确认、取消、切换失败与 interrupted 提示；保留原有带参数
   `/switch` 和其他命令断言不变。（`AC-001`、`AC-005`）
5. 比较切换前后的持久化字段，并运行既有 Session、澄清及完整测试，证明 Spec 隔离、持久化
   Schema 和澄清交互未变化。（`AC-006`、`AC-007`）

实现完成后运行项目现有的格式检查、Lint、类型检查和完整测试集。此改动不改变模型 Prompt、
工具选择或 Agent 行为，因此不新增概率性 Agent Eval；CLI 与终端交互使用确定性自动化测试
覆盖即可。

## 建议实施顺序

1. 先实现并测试 Session 列表视图模型、排序和分页状态。
2. 实现 TTY Picker 与非 TTY 回退，并完成适配器级测试。
3. 接入 CLI 的无参数 `/switch`，复用现有切换结果路径。
4. 补齐回归测试并执行全部工程门禁。

所有阶段均不得修改 `SessionRecord`、`session.json`、`index.json` 或 SessionManager 的状态转换；
若实现中发现必须突破这些边界，应停止实现并把问题反馈到 Spec，而不是在 Plan 中扩大范围。
