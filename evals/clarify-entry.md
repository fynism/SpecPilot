# 显式需求入口评测

`tests/clarify-entry.test.ts` 使用受控模型经过真实组合根、入口、Executor 和 Session，验证：

- 普通聊天可调查仓库；异常写入、轮次发布和导出调用被拒绝。
- 已有 pending 提交时，聊天成功、失败或进程退出均不消费答案、不修改 Spec。
- 无关、过宽、不同需求及非法入口响应不改变业务状态；模型工具响应不能绕过入口。
- 显式入口通过后开放需求能力；空轮次由现有宿主校验决定待审阅或未完成，随后聊天仍只读。
- 两个前端的无参数入口不调用模型；已完成时回到对话，不弹空问卷。

这些是机制与轨迹验证，不证明模型语义判断的准确率。真实模型诊断使用合成 fixture，单独开启：

```powershell
$env:SPECPILOT_RUN_ENTRY_EVALS = '1'
npx vitest run tests/clarify-entry-live.test.ts
Remove-Item Env:SPECPILOT_RUN_ENTRY_EVALS
```

真实诊断覆盖闲聊、仓库调查、带命令的无关内容、宽泛目标和明确需求；每例限制模型调用数和
单次超时，保存调用数、用量、工具轨迹和状态结果。入口调用应只发生在带参命令上，普通聊天
不得调用澄清/写工具，拒绝的入口不得开放写能力。明确需求应进入正式澄清。禁止行为按轨迹
和状态确定性评分，问题质量、是否遗漏关键事项仍需人工复核。单次运行只供诊断；正式质量
结论需要重复运行和人工标注，不以脚本通过率替代意图识别准确率。
