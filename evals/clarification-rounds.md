# 多轮澄清评测

## 两类证据

`clarification-evals.test.ts` 的离线脚本实际经过组合根、Executor、领域校验和 Session 提交，
验证多轮机制、权限限定保留、追问关联、分支停用、仓库调查和阻塞检查。
这些是机制契约，不衡量真实模型能否自主发现问题。

`session-v4.test.ts` 补充两项能力组合后的离线场景：发布问题即暂停并拒绝后续调用；
回答草稿经压缩、重启后仍能按轮提交；计数使用多轮模式实际提示词与工具声明；
运行失败后保留真实提交及已发生用量，撤回未提交摘要；两种 v2 与 v3 严格迁移到 v4。
这些场景使用 Fake Model，不连接真实服务，也不证明模型摘要的语义质量。

真实模型对比独立开启，使用同一模型、受控仓库、模糊导出需求及固定用户答复；分别运行旧单题
模式和默认多轮模式。每种模式独立限制为最多 24 次模型调用、四分钟，多轮最多三轮用户提交。
单次请求超时三十秒且不自动重试。输出包含调用数、
输入／输出 Token、运行耗时、工具轨迹、实际展示的问题及 Spec，人工依据下面的标准复核质量。
Token 使用量来自 SDK 标准输入／输出计数，不估算缓存计费。费用取决于供应商价格，不能
从 Token 数直接推定。脱敏报告保存在 `.specpilot/evals/`，预算停止时保存未完成报告。

```powershell
$env:SPECPILOT_RUN_LIVE_EVALS = '1'
npx vitest run tests/clarification-evals.test.ts -t '真实模型'
Remove-Item Env:SPECPILOT_RUN_LIVE_EVALS
```

默认测试不读取真实凭据或访问外部服务。显式开启时，从启动工作区读取模型配置，仅发送合成
需求及 fixture。网络异常只保留类型；不能把 SDK 原始错误、密钥或真实工作区内容写入报告。

## 质量复核标准

| 指标 | 判定 |
| --- | --- |
| 阻塞歧义召回 | 检查上传／导出参与者、数据范围、权限拒绝行为等影响验收的事项；记录发现数／应发现数 |
| 不必要提问率 | 已在用户答复说明或仓库中可直接查明的内容重复询问，计为不必要；不能靠提问数增加召回 |
| 决策来源 | 用户决定必须对应实际答复，保留“仅当前页面”和“普通用户返回 403”等限定 |
| 动态适应 | 确认管理员与本地导出后，云端保留、团队共享等不适用事项不应继续要求作答 |
| 可见与可控 | 主题总览保留待细化项，轮次清单只包含当前可答问题；暂缓不能伪装完成 |
| 代价 | 分别比较模型调用、Token、工具调用、用户问题数和耗时；不以更长清单作为提升 |

语义质量需要人工标签。单次真实模型结果只用于诊断；正式质量结论应重复运行、保存脱敏结果，
报告通过率与变化范围。存在越权、伪造确认或阻塞事项漏检时，不能用平均指标掩盖失败。

## 2026-10-14 诊断样本

同一受控导出需求、相同完整用户答复的最后一次对比，两种模式最终均通过准备条件检查，
没有工具校验失败；保留了明确的低影响假设警告。

| 模式 | 模型调用 | 展示问题 | 输入 Token | 输出 Token | 耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 多轮总览 | 9 | 4 | 19,499 | 15,391 | 80.4 秒 |
| 单题基线 | 11 | 1 | 9,435 | 12,970 | 68.6 秒 |

本例多轮调用更少，但 Token 与耗时更多。交互掌控力应单独评估，不能据此宣称成本或质量
普遍改善。这是一个合成诊断样本，后续模型行为和少量确定性边界修正仍须持续回归。
